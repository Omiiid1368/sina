نسخهٔ `0.11.0-offline-preview`، کد نسخهٔ ۳، شناسهٔ `ir.hezarzist`. تاریخ گزارش ۸ نوامبر ۲۰۲۶ است. ساخت و اجرای اولیهٔ Debug در UTC روز ۷ نوامبر و بررسی دستی Release امضاشده در UTC روز ۸ نوامبر ثبت شده‌اند؛ زمان دقیق هر اجرا در شاهد همان بخش محفوظ است.

## آزمون‌های اولیهٔ دستگاه روی Debug و اصلاح انتظار آزمون

آزمون‌های instrumentation این بخش روی **شبیه‌ساز Android 10 / API 29 با نمایشگر ۷۲۰×۱۲۸۰ و تراکم ۳۲۰dpi** و نسخهٔ Debug اجرا شده‌اند؛ [مشخصات دستگاه](test-evidence/device-info.json) محفوظ است. آزمون روی گوشی واقعی یا Android API 35 انجام نشده است. امضا، ارتقا و بررسی دستی Release جداگانه ثبت شده‌اند. روی APK امضاشدهٔ Release نیز هر ۴۰ آزمون اجرا و سپس یک آزمون اصلاح‌شده جداگانه تکرار شده است؛ آخرین نتیجهٔ همهٔ ۴۰ آزمون یکتا قبول است. جزئیاتِ اجرای کاملِ ۳۹ قبول و ۱ شکست و بازاجرای موفقِ همان ۱ آزمون در بخش Release آمده است.

اجرای اول ۴۰ آزمون داشت: **۳۹ قبول و ۱ شکست**، بدون skip. شکست `rotationKeepsQuickSessionAndDeadline` برابری دقیق deadline را می‌خواست؛ پس از بازآفرینی Activity زمان پایان فقط **۱ میلی‌ثانیه زودتر** بود. انتظار آزمون به بازهٔ محافظه‌کارانهٔ `-100ms..+5ms` اصلاح شد و الزام مصرف حداقل ۵۰۰ میلی‌ثانیه، هویت نشست، شمارهٔ سؤال، مسیر و تیک‌خوردن زمان باقی ماند. این تغییر فقط در آزمون بود و کد برنامه تغییر نکرد.

سپس فقط کلاس `PersianUiTest` دوباره اجرا شد: **۳ از ۳ قبول**، صفر شکست و skip. آخرین نتیجهٔ هر **۴۰ آزمون یکتا قبول** است؛ همهٔ ۴۰ آزمون بعد از اصلاح در یک اجرای تازه تکرار نشده‌اند. مجموع دو اجرا **۴۳ اجرای آزمون، ۴۲ نتیجهٔ قبول و همان یک شکست اولیهٔ رفع‌شده** است. جزئیات در [device-summary.json](test-evidence/device-summary.json)، [XML اجرای اول](<test-evidence/device-initial/TEST-HezarZist(AVD) - 10-_app-.xml>) و [XML اجرای دوبارهٔ فارسی](<test-evidence/device-persian-rerun/TEST-HezarZist(AVD) - 10-_app-.xml>) حفظ شده‌اند.

## ارتقای واقعی Release امضاشده

[release-upgrade.json](test-evidence/release-upgrade.json) ارتقا با `adb install -r`، **بدون حذف نصب و با همان گواهی** از `0.9.0-beta` کد ۱ به نسخهٔ آفلاین کد ۳ را ثبت کرده است. یک سؤال قدیمیِ دارای سابقه به بایگانی رفت؛ نشان آن حفظ و متن خام نشست نیمه‌تمام دقیقاً نگهداری شد. جمع‌ها، رکوردها، تاریخچه و تنظیمات موجود تغییر نکردند.

محدودیت این شاهد مهم است: مبنای آزمون تنها یک نشست تمرین نیمه‌تمام داشت؛ مسابقهٔ کامل‌شده و امتیاز تجمعی متفاوت از مقدار اولیه در آن مبنا وجود نداشت. بنابراین این ارتقا حفظ تمام سناریوهای کاربران واقعی یا رکوردهای غیرصفر را به‌تنهایی ثابت نمی‌کند. سناریوهای متنوع‌تر در آزمون‌های مهاجرت و پشتیبان بررسی شده‌اند، اما با ارتقای هر گوشی واقعی یکسان نیستند.

## بانک، آرشیو و بازبینی علمی

- اعتبارسنجی معمول بانک **قبول** است: ۹۶ تست + ۷۲ نهایی، **۱۶۸ شناسهٔ یکتا**، چهار گزینه و تحلیل متناظر برای هر تست، پاسخ معتبر و تصویر ضروری موجود. [bank-validation.json](bank-validation.json) هش و شمار فصل‌ها را دارد؛ [CHAPTER_COUNTS.fa.md](CHAPTER_COUNTS.fa.md) از بانک مرجع محاسبه شده است.
- ابزار پوشش رسمی **۲۳ آزمون Python، صفر شکست و صفر خطا** دارد؛ [COVERAGE_TESTS.json](COVERAGE_TESTS.json) و [خروجی اجرا](test-evidence/coverage-python.txt). داده‌های ساختگی آزمون فقط در پوشهٔ موقت آزمون بوده‌اند و وارد بانک یا APK نشده‌اند.
- دروازهٔ `--complete` **طبق انتظار با کد ۱ شکست می‌خورد**: سؤال رسمی واردشده صفر است و فهرست معتبر تمام نوبت‌های هر هشت سال هنوز نامعلوم است؛ [خروجی دروازه](test-evidence/coverage-complete-gate.txt) و [پوشش](COVERAGE.fa.md). این شکستِ حفاظتی با قبولی ۲۳ آزمون ابزار اشتباه نشود؛ آرشیو جامع فراهم نشده است.
- دروازهٔ نهایی `tools/validate_bank.py --release` نیز **طبق انتظار موفق نیست**؛ [final-completion-gate.txt](test-evidence/final-completion-gate.txt) چهار خطای مسدودکننده را ثبت می‌کند: کامل‌نبودن آرشیو رسمی، تأییدنشدن راهنمای رسمی مایکت، آماده‌نبودن حساب توسعه‌دهنده و ناتمام‌بودن پوشش آرشیو. قبولی آزمون APK و پشتیبان اکنون ثبت شده است و در این چهار خطا قرار ندارد؛ `readyForPublicSubmission` همچنان `false` است. اعتبارسنجی معمول بانک دوباره اجرا شده و [گزارش معمول](bank-validation.json) خطای ساختاری ندارد.
- بازبینی مفهومی با هوش مصنوعی برای محتوای تألیفی موجود ثبت شده؛ **بازبینی انسانی و تطبیق چاپ رسمی کتاب انجام نشده‌اند**. بازبینی علمی سؤال کنکور واقعی نیز با صفر سؤال و نبود اصل دفترچه/کلید انجام‌شده معرفی نمی‌شود. [محدودیت‌های منابع](archive/README.fa.md) و [اعلام حق استفاده](archive/RIGHTS.fa.md) صریح‌اند.

## اجرای نهایی روی Release امضاشده و سوابق اصلاح آزمون

تلاش اول برای آزمودن Release امضاشده، ۴۰ آزمون را اجرا کرد و **۳ شکست** داشت؛ [خروجی اولیه](test-evidence/signed-release-initial-abi-mismatch.txt) حفظ شده است. test APK آن تلاش برای Debug کامپایل شده بود و فقط دوباره امضا شده بود. سه آزمون پشتیبان هنگام فراخوانی hook/getter داخلی Kotlin با `NoSuchMethodError` متوقف شدند: نام‌های داخلی مورد انتظار پسوند `$app_debug` داشتند، در حالی که APK هدف Release با پسوند `$app_release` ساخته شده بود. بنابراین این سه مسیر در آن تلاش معتبر اجرا نشدند و نتیجهٔ آن تلاش قبولی کامل Release نیست.

پیکربندی ابزار آزمون با [init script بیرونی Gradle](test-evidence/release-instrumentation.init.gradle) و `testBuildType=release` اصلاح شد؛ `assembleReleaseAndroidTest` در [گزارش ساخت تست](test-evidence/release-test-build.txt) موفق است. test APK مطابق Release کامپایل و با همان کلید امضا شد؛ **کد برنامه برای این اصلاح تغییر نکرد**. [تطبیق بایت APK نصب‌شده](test-evidence/installed-release-target.json) تأیید می‌کند هدف همچنان همان APK با هش `9012364db913ab1809b48437aa6c8db683d0ee0caa8995d00952835cdbd0316c` است.

پس از اصلاح variant، [اجرای کاملِ Release](test-evidence/signed-release-full-39-of-40.txt) هر **۴۰ آزمون** را با **۳۹ قبول، ۱ شکست و صفر skip** اجرا کرد. شکست `FinalStudyTest.reviewFiltersUseLocalUnassessedAttemptsAndBookmarksWithoutRepeats` ناشی از ورودی ناکامل خود آزمون بود: سؤال تصادفی از نوع `true_false` انتخاب شد اما آزمون انتخاب درست/نادرست را ثبت نکرده بود؛ شرط محافظ ارسال برنامه پاسخ را نپذیرفت و انتظار بعدیِ آزمون دربارهٔ اولویت سؤال حل‌شده برقرار نبود.

اصلاح فقط در کد آزمون انجام شد: برای سؤال درست/نادرست، `chooseTruth(false)` و متن اصلاح ثبت و `canSubmit` و موفقیت `submitted` پیش از بررسی اولویت تأیید شدند. بررسی‌های اولویت، فیلتر، نشان و نبود تکرار حفظ شدند؛ **کد برنامه و APK هدف تغییر نکردند**. [بازاجرای هدفمند همان یک آزمون](test-evidence/signed-release-final-targeted.txt) **۱ اجرا، ۱ قبول، صفر شکست و صفر skip** دارد.

طبق [signed-release-summary.json](test-evidence/signed-release-summary.json)، **آخرین نتیجهٔ همهٔ ۴۰ آزمون یکتا روی خود APK امضاشدهٔ نصب‌شده قبول است**: ۱۰ منطق بازی، ۹ آمادگی نهایی، ۱۳ پشتیبان محلی، ۵ انطباق آفلاین و ۳ رابط فارسی. **همهٔ ۴۰ آزمون بعد از اصلاح ورودی در یک اجرای تازه تکرار نشده‌اند.** مجموعهٔ درستِ Release و بازاجرای هدفمند روی‌هم ۴۱ اجرای آزمون دارند: ۴۰ نتیجهٔ قبول و یک شکستِ ورودیِ آزمون که با بازاجرای آن رفع شده است. تلاش قبلیِ دارای سه خطای ABI جداست و از این شمار تفکیک شده است؛ خروجی آن حذف یا قبولی معرفی نشده است. این نتایج محدود به همان شبیه‌ساز API 29 هستند و جای آزمون گوشی واقعی یا Androidهای دیگر را نمی‌گیرند.

## محدودیت تحویل کامل

شرط جامعیت کنکور ۱۳۹۸ تا ۱۴۰۵، منابع رسمی نهایی، چاپ رسمی و بازبینی انسانی همچنان کامل نیست. خواندن ضوابط رسمی به‌روز مایکت نیز به علت محدودیت دسترسی انجام نشده و ارسال به مایکت صورت نگرفته است. این موارد با قبولی ساخت، امضا، آزمون‌های فنی یا بسته‌بندی برطرف نمی‌شوند. نسخهٔ حاضر فقط پیش‌نمایش آفلاینِ قابل بررسی است؛ بستهٔ نهایی جامع یا آمادهٔ انتشار عمومی معرفی نمی‌شود.

دروازهٔ نهایی `validate_bank.py --release` نیز با وضعیت فعلی **عمداً رد می‌شود**: آرشیو کامل و راهنمای رسمی مایکت و حساب فروشگاه تأیید نشده‌اند. [خروجی دروازهٔ تکمیل](test-evidence/final-completion-gate.txt) با آزمون موفق عملکرد برنامه متفاوت است.
